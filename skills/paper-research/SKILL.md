# 论文调研与网站归档

用户已在 2026-10-18 确认 Pilot-Based 无线定位与建图报告为后续论文调研基准。沿用其分析深度与可读性，不机械复制特定公式、图数或无线模型。

## 核心交付标准

1. 阅读完整原文，核实论文身份与版本。优先使用作者/出版方/arXiv/大学的一手来源，不用摘要替代全文；无法获得的内容说明缺口。
2. 详细建模：明确问题、输入输出、已知未知、变量、假设、约束、噪声与目标；核心关系用公式并解释符号、单位、维度和意义。
3. 方法跟进到可理解的求解链：每阶段交代输入 → 变换/表示/目标 → 求解算法 → 输出、作用与失败条件；关键公式对应原文编号。区分原文、等价重写、自行推导与建议；发现记号/量纲疑点时显式说明。
4. 实验可追溯：场景/数据、实测或仿真、参数、样本/统计范围、指标和结果。数字必须有来源；报告自行计算要标明，未报告不猜测。
5. 原图与比较：取得可使用的原文关键结果图，保留坐标、图例、图注，注明版本、来源、图号/页码及许可；按需加入系统/场景图。逐图解释基线/阶段、改善、代价和残留错误。有图时不能只写文字或只放链接；无法取得或展示时如实说明，不伪造或用 AI 重绘替代。
6. 不虚构基线、消融或 SOTA。能力差异不是性能胜出，删点比例不是准确率提升，单次示例不是统计平均。分别讨论作者结论、图中观察、报告判断与后续研究建议。
7. 用具体复现、消融与压力测试建议收尾，指出实现缺口和部署条件。结构随论文类型调整，覆盖以上要点而非堆砌标题。

## 网站与可复用实现

为用户制作完整论文调研报告、要求“按之前方式”且无相反限制时，延续其已确认流程：中文报告、源码归档、对应栏目及 GitHub 网站发布。仅讨论、草稿、本地保存或明确不发布的当前请求不触发部署。

用户网站为 `lucky-xing/lucky-xing.github.io`（`https://lucky-xing.github.io/`），不是 Sites 工作台。发布或修改网站时阅读 [references/github-site.md](references/github-site.md)，并遵守仓库 `AGENTS.md` 与 `reports/paper-research/README.md`。通感论文放 `通信 → 通感`，其他论文按研究对象归类。

保留网站共享导航、品牌、深色紫调及字体。正文继承网站无衬线字体，桌面 18px、移动 17px、中等字重、清晰浅色；标题不挤压字距。公式正常数学排版，长公式/表格局部滚动，原文科学图保留原色并可放大。

复用仓库 `scripts/render-paper-report.py` 与 `assets/paper-report.css`，避免重复拼装和修改既有满意报告。生成器不代替研究、不自动更新栏目、不执行提交推送。维护 Markdown 源、原图来源说明和栏目入口。

发布完成须核实本次 commit 的远端 SHA、Pages 部署、线上公式与图片和目录链接；不能以旧部署成功充当新版本成功。使用已有认证，不保存或索要已有 Token。网络受限时先区分网络与认证问题。
